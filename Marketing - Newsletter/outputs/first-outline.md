# First Outline: Keeping AI Context Across Tools

**Status:** Draft outline for review. Not approved.
**Audience:** Busy marketers who use chat-based AI and have never used GitHub.

## Working headline options

- Stop re-explaining yourself to AI
- Your AI context should live in files you own
- One folder, every AI tool

## Point 2: Put the context in plain files you own

- Define "plain text file": a simple document with no special formatting, readable
  by any tool.
- Three starter files:
  - **CLAUDE.md** (or an equivalent instructions file): who you are, who you write
    for, how you write, what never to do.
  - **handoff.md**: where the work stands and what happens next.
  - **decisions.md**: choices you have confirmed, kept separate from suggestions.
- Example to show: a trimmed version of this project's own CLAUDE.md.

## Point 3: Reuse the same files in any AI tool

- Paste or upload the files at the start of a session, or point a tool at the folder
  if it can read files directly. **[FACT-CHECK: confirm which tools support each method]**
- The tool changes. Your context does not.
- **[MISSING: which tools to name]** List the specific tools you have tested this
  with, so the article only describes what you have actually done.

## Point 4: Use GitHub as a save history, not a developer tool

- Define "GitHub": a website that stores folders and keeps every saved version.
- Define "commit": a saved checkpoint with a short note about what changed.
- GitHub Desktop lets you review changes and save them without typing commands.
- Why it matters for marketers: you can see what changed, when, and roll back.
- Keep decks, video, and client-edited documents in Google Drive. This folder holds
  reusable context, notes, and text outputs only.

## Point 5: Start small with one project

- Pick one recurring piece of work (for example, a newsletter).
- Write the three files in one sitting. Keep them short.
- End each session by updating the handoff and recording confirmed decisions.
- Never store passwords, API keys, or confidential client information in these files.
